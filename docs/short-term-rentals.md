# Short-term rental flow

The stay workflow uses Supabase Auth, private application proof storage, an admin review inbox, published stay listings, and Stripe Connect destination charges.

1. A host signs up and verifies their account email, then submits the property application and uploads proof/photos. The application stays a draft until uploads finish. Submission commits the profile status and notification outbox together.
2. Admin → Short-term host applications shows submitted applications. Admins can open private proof, approve, decline, or request more information. A decision updates both the application and the host profile. Rejected applicants can correct and resubmit. The inbox refreshes while open; notification delivery can be retried without resending successfully delivered messages.
3. An approved host completes Stripe Express onboarding, including their bank details. Onboarding uses their application country. Publication and checkout require an account with active transfers and payouts enabled.
4. Hosts publish a stay with persistent photos, a price, cleaning fee, guest capacity, house rules, and dates. Their profile exposes availability, pause, publish, and archive controls. These new listing controls apply to stays.
5. Signed-in guests choose dates and guest count. The server validates availability and calculates the immutable booking price: nightly rate × nights + cleaning fee + a 12% guest service fee on the nightly subtotal. An unpaid checkout holds dates for 30 minutes.
6. Request-to-book authorizes a card. The host approves to capture, or declines to release the authorization. Instant-book listings capture at checkout. My Stays exposes payment retry, messaging, and cancellation. Captured self-service guest cancellations close 24 hours before the UTC start date; eligible cancellations refund the charge and reverse the host transfer and platform fee.
7. Stripe receives the service fee as the platform application fee and routes the remainder to the host's connected account. The Stripe dashboard manages the host's bank payouts. Bank settlement follows Stripe's account payout schedule; this implementation does not schedule Airbnb-style delayed release after check-in.

A checkout quote no longer invents an 8% tax. Taxes are not configured or collected by this implementation. The UI labels totals before taxes. Resolve the operating tax policy before commercial launch.

## Validation

Run `npm install` and `npm test` on Node 24. The tests execute the rental schema and RLS in embedded PostgreSQL and exercise the actual payment handlers with controlled Stripe/email responses. They cover application drafts, proof ownership, admin decisions, resubmission, publishing gates, server pricing, date conflicts, expired holds, payment locks, captures, cancellation/refund retries, out-of-order webhooks, notification retries, and frontend failure recovery.

The browser acceptance checks used the production page on a local server with external requests blocked. They checked the mobile application form, admin review controls, guest payment retry/cancellation, and host availability/pause/archive controls. Example accounts and bookings were browser fixtures. These checks do not constitute a real card, email-inbox, or bank-settlement test.

## Release and live acceptance

Apply `20260912180000_complete_short_term_rental_flow.sql`, then deploy `connect-account`, `send-host-email`, `create-payment-intent`, `manage-booking-payment`, and `stripe-webhook`, including their shared modules. Publish the matching frontend afterwards. Use the linked migration history; do not blindly push unrelated older workspace migrations.

Required existing server settings: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `RESEND_API_KEY`, `HOST_EMAIL_FROM`, and the Supabase service credentials. Their names were present during the release check; actual delivery and settlement still need acceptance testing. A private failed-delivery outbox remains available if email fails.

Before taking customer bookings, use a separate Stripe sandbox/Supabase test project to verify email receipt, one complete real-account application and approval, onboarding, photo publication, guest authorization, host capture, a refund, and the connected-account payout state. The production browser key is live, so do not use real customer charges as test transactions. At inspection there was one admin, zero host applications, zero stay listings, and zero completed payout setups.

Stripe references: [destination charges](https://docs.stripe.com/connect/destination-charges), [authorization windows](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method), [connected-account payouts](https://docs.stripe.com/connect/payouts-connected-accounts).


## Setup still required

1. **Create the acceptance environment.** Create a separate Supabase project and Stripe sandbox. Apply the matching production schema and this migration to the test project without importing production users or bookings. Deploy the five functions there. Host a staging copy of the frontend with that project's URL/public key in `supabase-config.js` and the sandbox publishable key in `stripe-config.js`. Configure the staging URL in Supabase Auth and the payout redirect allowlist. Never put secret keys in frontend files or Git.
2. **Configure Stripe events.** In each environment, the platform webhook destination is `https://<project-ref>.supabase.co/functions/v1/stripe-webhook`. Enable `payment_intent.succeeded`, `payment_intent.amount_capturable_updated`, `payment_intent.payment_failed`, `payment_intent.canceled`, `payment_intent.processing`, `charge.refunded`, `charge.dispute.created`, and `charge.dispute.closed`. Preserve the existing checkout/subscription/invoice events used elsewhere on 6ixo. Store its signing secret as `STRIPE_WEBHOOK_SECRET`. Add a destination for **Connected accounts → account.updated** to the same URL and store that destination's distinct secret as `STRIPE_CONNECT_WEBHOOK_SECRET`. Set `STRIPE_SECRET_KEY` from the matching Stripe environment. The new Connect secret was not present at inspection. [Stripe Connect webhook setup](https://docs.stripe.com/connect/webhooks).
3. **Verify email and admin access.** Verify the sender domain in Resend, set `RESEND_API_KEY` and `HOST_EMAIL_FROM`, and confirm Supabase's signup confirmation sender/hook. The host and each admin need verified account emails. Admin access is granted by trusted server administration through `profiles.is_admin`; applicants cannot grant it. Check both host and admin inboxes during submission and approval. Failed application emails remain in the outbox and can be retried from Admin; automatic background retries are not configured.
4. **Complete host onboarding.** Use a sandbox host first, then each real host completes Stripe Express identity and bank onboarding. Confirm the platform supports transfers to each host's legal country/currency. A listing stays blocked until transfers are active and payouts are enabled. Check actual bank payout progress in the host's Stripe dashboard.
5. **Approve the commercial rules.** The implemented guest service fee is 12% of accommodation charges, with cleaning charged separately. Confirm the cancellation policy, operating regions/currencies, tax collection requirements, and host payout schedule. Tax collection and a release schedule after check-in are not implemented. The platform fee is gross fee revenue; Stripe processing/refund/dispute costs must be accounted for separately.
6. **Run acceptance before opening bookings.** Use separate host, guest, and admin accounts to test signup/verification → application with proof/photos → admin receipt and needs-info/decline/resubmission/approval → payout onboarding → listing publication → guest authorization → host capture → host connected-account balance. Also exercise instant booking, declined cards, expired authorization/checkout, overlapping dates, cancellation/refund, notification retry, and payout failure handling in Stripe. Use Stripe's supplied test credentials in the sandbox. No live card or bank transaction was performed for this release. [Stripe testing guide](https://docs.stripe.com/testing).
